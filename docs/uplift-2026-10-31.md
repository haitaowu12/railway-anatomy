# Railway hierarchy, alternatives and depot uplift

## Purpose and scope

This revision starts from public repository commit `53eee2be3aaa26e5016f7c599e7ddeddb31ae363`. It addresses three problems: the explorer did not explain how areas belong to a railway, some technology choices changed explanatory text without replacing the corresponding equipment, and depot coverage lacked enough distinct facilities and mechanisms.

The revised application contains 193 concepts, 113 public reading references, 37 model views, nine navigation domains and 26 guided tours. All new geometry is an original, fictional teaching composition. It is not a survey, equipment specification, work procedure or representation of an installed railway.

## Navigation and interaction decisions

The starting view is a whole railway with stations, running lines, a turnback, trains, a depot branch, stabling, maintenance, a control centre, traction supply and telecommunications. Movement, traction-power and information overlays explain different connections across that same railway.

The navigation separates **places and fleet** from **systems across the railway**. A station and a vehicle are locations in which several systems meet; power and communications cross those locations. Each area expands to its own model views. Breadcrumbs, explicit drill-down actions and return links connect scales without requiring a rigid tree for every shared component.

Selecting a bogie inside the maintenance hall keeps the maintenance context. Opening its primary detail view creates a return link to the hall. Search and field-guide links open a component's primary model. Browser Back and Forward restore the view, variant, component, technology choices and associated presentation state. Opening the field guide also preserves the underlying explorer context.

Technology choices remain independent. LIM and rotary propulsion can be compared with loop control, radio control, conventional signalling and ETCS examples. The general scenes replace the corresponding physical hardware and information paths. Selecting ETCS does not silently change propulsion or the illustrative DC power supply. The interface explains when a choice opens a more useful detail view. A combination is an educational comparison, not a claim of commercial compatibility.

On narrow screens, a collapsed railway browser preserves model space. The selected component and a direct explanation link remain beside the model. Cutaway and separation controls appear only when the current model registers relevant parts.

## Visual design comparison

Two structural candidates were reviewed with the same whole-railway content and desktop viewport:

| Candidate | Observation | Decision |
|---|---|---|
| Side hierarchy | Preserves the distinction between places and cross-cutting systems, exposes local views, and leaves more model height visible | Selected |
| Chapter navigation above the model | Adds horizontal model space but consumes vertical space; lower model controls fall below the first viewport | Rejected |

The final direction uses a restrained technical palette, readable explanatory text, plain component rows, a dominant model stage and an independently scrolling desktop inspector. Technology selection is a compact disclosure. Generic scope notes are available without repeating long warnings in the main reading path. Model alternatives sit directly above the scene they change.

## Depot coverage

| View | Coverage and meaningful alternatives |
|---|---|
| Whole depot | Reception and dispatch, yard throat, stabling, maintenance, workshop, wash plant, utilities and support; layout and night context |
| Arrival and yard | Reception and dispatch emphasis, access relationships and stabling |
| Maintenance hall | Inspection pits and roof access; bogie lowering and lateral transfer; body lifting with bogies on the floor; an installed-wheelset lathe arrangement |
| Wheel and bogie shop | Wheelset machining, a removed wheelset and a bogie work area |
| Wash plant | A train moving through fixed equipment, a gantry travelling alongside a stationary train, and a separate water-circuit emphasis |
| Facility services | Electrical services, compressed air, water, drainage and collection/discharge boundaries |
| Stores and work planning | Material availability, work instructions, records and return-to-service planning |
| Work zones and energy | Movement protection, indications and energy-control concepts, with their different responsibilities stated |

The bogie-drop model retains one attached bogie, supports the body, lowers one separated bogie and transfers it on a grounded carrier. The vehicle-lifting alternative raises the body while two bogies remain at floor level. These are separate equipment illustrations. Work-zone indications do not constitute verified energy isolation.

## Public evidence and scope

The new material uses public publisher pages and original explanatory text. Private project documents, names, layouts, quantities, interfaces and operational details are not included. Public examples retain their scope; a supplier illustration is not a universal railway arrangement.

Representative sources include:

- [IRSE Australasia: Rail Car Depot Infrastructure — The Dry Creek Experience](https://irse.org.au/resource/2011-july-zhang-baulderstone-rail-car-depot-infrastructure-the-dry-creek-experience/), for the public abstract on depot infrastructure and mainline/depot interfaces.
- [Nencki bogie lowering systems](https://www.nencki.ch/en/plant-engineering/lifting-and-lowering-system-1/bogie-lowering-system-nbd), for the relationship between vehicle support, lowering and transfer.
- [Aquafrisch stationary and mobile train washing](https://www.aquafrisch.com/en/stationary-mobile-and-manual-train-washing-systems/), for fixed and mobile arrangements and water-treatment context.
- [Hegenscheidt U2000-150 underfloor wheelset lathe](https://www.hegenscheidt.com/en/machine-portfolio/machines-for-wheelset-machining/underfloor-wheelset-lathes/u2000-150/), for machining a wheelset while it remains installed.
- [Sentric depot personnel protection](https://www.sentricsafetygroup.com/us/applications/depot-personnel-protection-system/), for protection equipment context.
- [ORR: Entities in Charge of Maintenance](https://www.orr.gov.uk/guide-rogs/8-entities-charge-maintenance-ecm), for maintenance responsibility and records.

The application links to publishers and does not reproduce their drawings or full publications. The static [reading directory](../dist/reading.html) is generated from the same catalog as the explorer.

## Verification

Run `npm run reading` after catalog changes, then `npm run check` under Node.js 24. No package installation is required. The check command includes:

- Static bundle, syntax, catalog/reference integrity, route targets, tour targets and generated-reading consistency.
- Procedural geometry construction, finite geometry and registered component availability.
- Actual technology geometry across 60 general-scene configurations, 10 named architecture/propulsion combinations, and 28 architecture variants in assembled and cutaway states.
- Production navigation serialization and reading: 160 view/variant/mode round trips, 40 vehicle technology/mode configurations, malformed-route fallback, ETCS radio bookmarks, parent trails and field-guide Back restoration.
- Depot invariants for rail/wheel contact, primary selectable meshes, variant visibility, one separated bogie, supported body lifting, grounded transfer equipment, lathe alignment and washing movement.

Browser acceptance covered whole railway → depot → maintenance → bogie detail → return; representative alternative changes; independent propulsion and control changes; Back/Forward; component search; the field guide; guided-tour exit; public source links; and narrow-screen navigation and explanation access. The narrow test used a 390 × 844 CSS-pixel frame; the content had no horizontal overflow.

The browser used the **SVG compatibility renderer**. Hardware-WebGL appearance, GPU-specific picking and performance on physical devices were not verified in this review. Geometry and source-level assertions do not establish railway engineering correctness or safety compliance. The schematic animation is explanatory rather than a quantitative engineering simulation.

## Deployment

The checked `dist/` directory is the GitHub Pages artifact. The repository workflow checks the code before deployment on a push to `main`. The older GPT Site is a separate deployment; a GitHub update does not automatically refresh that host.
